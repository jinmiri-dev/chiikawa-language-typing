# 언어 1급 — 서비스 기획안 v4

작성일: 2026년 11월 1일
이전 기획(v1 유튜브 단독, v2 대본 단독, v3)을 대체한다. 1차 범위: 5개 언어 × (기본 연습 + 유튜브 + 대본) 전부.

## 1. 한 줄 정의

한국인이 배우고 싶은 언어의 유튜브 영상이나 대본 파일로, 원문을 한 줄씩 타자로 치며 한국어 뜻·발음·키 입력 방법을 함께 익히는 외국어 타자 연습 사이트. 휴대폰에서도 같은 경험을 하고, 고른 먼작귀 친구가 옆에서 함께한다.

## 2. 왜 만드나

- **진짜 목표:** 휴대폰으로 외국인 친구와 채팅할 만큼 외국어 타자가 빨라지는 것이다. 지금은 일본어·대만어 타자가 매우 느린데, 원인은 "그 글자를 치려면 어떤 키를 어떤 순서로 눌러야 하는지(입력 조합)"를 모르는 데 있다.
- 그래서 이 사이트의 핵심은 **키보드 배열별 입력 조합 안내**다. 문장, 발음, 한국어 뜻만 보여 주는 학습 사이트와 여기서 갈린다.
- 일본어·중국어처럼 입력기를 거치는 언어는 읽는 법을 알아야 칠 수 있다. 그래서 타자 연습이 곧 발음 공부가 된다.
- 연습 재료는 사용자가 좋아하는 것이어야 오래 간다. 유튜브 영상(노래, 드라마, 예능 등)과 넷플릭스 대본을 쓴다.

## 3. 사용자와 대표 장면

- 사용자는 한국인이다. 화면 언어와 설명은 한국어로 고정하고, 사용자는 배우고 싶은 언어 하나만 고른다.
- **유튜브로 공부:** 일본어를 고르고 "노래" 태그를 누르거나 검색한다. 영상을 고르면 일본어 원문과 한국어 뜻이 준비된다. 한 소절씩 듣고, 휴대폰 12키 플릭으로 따라 친다. 화면은 `べ → は행 키를 오른쪽으로(へ) → ゛`처럼 다음 입력을 안내한다.
- **대본으로 공부:** 넷플릭스에서 이중 자막으로 미드를 보고 대본(PDF, SRT 등)을 내려받는다. 사이트에 올리고 한 줄씩 친다.
- **수업:** 선생님이 교재 본문과 번역을 넣어 연습을 만들고 파일(또는 짧으면 링크)로 준다. 학생은 각자 기기에서 혼자 연습한다. 혼자 공부와 같은 화면이며, 차이는 "공유하기"뿐이다.

## 4. 목표 / 비목표 / 실패 조건

**목표**
- 처음 온 사람은 언어 선택 → 기본 연습으로 두 번 만에 첫 줄을 친다. 유튜브 영상이나 대본도 3단계 안에 첫 줄을 친다.
- 연습할수록 실제로 빨라진다(20.2 효과 기준).
- 원문, 발음, 한국어 뜻이 한눈에 묶여 보이고, 입력이 그 바로 아래에 있다.
- 고른 키보드 배열(PC·휴대폰)에 맞춰 다음에 누를 키와 입력 조합을 안내한다.
- 휴대폰 키보드가 올라와도 문장, 뜻, 입력 상태, 안내가 보인다.
- 로그인 없이 바로 열린다. 첫 화면이 서버를 기다리지 않는다.

**비목표 (1차에서 하지 않음)**
- 로그인, 사용자 DB, 기기 간 동기화, 선생님용 학생 결과 모아 보기
- 넷플릭스 영상 재생(외부 사이트 재생이 불가능하다)
- 발음·노래 음성 인식 채점
- 속도 순위, 다른 사용자와의 경쟁

**실패 조건 (작동해도 실패로 본다)**
- 키보드 안내가 틀린 키를 알려 준다. 검증되지 않은 배열·조합은 안내를 숨긴다.
- 휴대폰에서 키보드가 올라오면 지금 칠 문장이 가려진다.
- 캐릭터나 팝업이 타자 흐름을 끊는다.
- 자막·대본이 엉망으로 나뉘었는데 고칠 방법 없이 연습으로 넘어간다.
- 유튜브 자막 서비스 사용량이 넘쳐 예고 없이 요금이 나온다.
- 사용자가 넣은 대본 파일을 외부로 보낸다.

## 5. 운영 원칙·제약

- 화면은 정적 사이트로 만들어 GitHub Pages(저장소 `jinmiri-dev/chiikawa-language-typing`)에 배포한다.
- 유튜브 검색과 자막 가져오기만 Cloudflare Workers 중계 함수 하나를 거친다(8장). 잠들었다 깨는 상시 서버(Render 등)는 쓰지 않는다.
- API 키는 중계 함수에만 두고 화면 코드에 넣지 않는다.
- 사용자 데이터(대본, 진도, 단어장)는 브라우저 저장소와 사용자가 내려받는 파일에만 남는다. 대본 파일은 중계 함수로도 보내지 않는다.
- 비수익, 개인·수업 사용이 목적이다. 유료 서비스는 무료 한도 안에서 쓰고, 중계 함수에 하루 사용 상한을 둔다.
- 저작권: 넷플릭스 대본과 노래 가사는 개인 공부용이다. 사이트는 사용자 대본을 보관·공개하지 않고, 공유 기능에 "대본 전체를 여러 사람에게 배포하지 마세요"를 표시한다.
- 먼작귀는 원작 저작권이 있는 IP이고, 보유 이미지는 생성 도구로 만든 비공식 시안이다. 공개 배포 전에 이용 조건을 확인한다(17장).

## 6. 지원 언어와 키보드 (1차 5개)

| 언어 | 원문 | 발음 표시 | PC 키보드 | 휴대폰 키보드 |
|---|---|---|---|---|
| 영어 | 영어 | 없음(2차에서 검토) | 쿼티 | 쿼티 |
| 일본어 | 가나·한자 | 후리가나(히라가나), 로마자 | 로마자 입력 | 12키 플릭, 12키 탭 반복, 로마자 쿼티 |
| 중국어 (간체) | 간체 | 성조 병음 | 병음 쿼티 | 병음 쿼티, 병음 9키(3×4) |
| 대만어 (번체) | 번체 | 주음(ㄅㄆㄇ), 병음 | 주음(표준 大千 배열), 병음 쿼티 | 주음 자판, 병음 쿼티 |
| 몽골어 | 키릴 문자 | 로마자 전사 | 몽골어 키릴 자판 | 몽골어 키릴 자판 |

- 화면 표기와 순서는 위 표 그대로 한다: 영어, 일본어, 중국어 (간체), 대만어 (번체), 몽골어. 각 이름 옆에 그 언어의 표기(English, 日本語, 简体中文, 繁體中文, Монгол хэл)를 함께 보여 준다.
- "대만어"는 대만에서 쓰는 중국어(번체 + 주음 입력)다. 대만어(민난어)가 아니다. 이용 안내에 한 줄로 설명한다.
- 대본 글자는 바꾸지 않는다. 대만어 (번체) 연습에 간체 대본을 넣으면 간체 그대로 연습한다.
- 키보드 배열과 입력 조합은 언어·배열별로 실제 기기에서 검증한 뒤 연다(15장). 검증 전 배열은 "안내 준비 중"으로 표시하고 타자만 할 수 있게 한다.
- 이후 후보: 광둥어, 러시아어, 베트남어(Telex·VNI), 태국어.

## 7. 화면 흐름

```
시작(언어 선택) → 재료 고르기 ─┬─ 기본 연습(채팅 표현) ──────────┐
                               ├─ 유튜브: 태그·검색·링크 ─────────┤
                               └─ 대본: 파일·붙여넣기 → 확인·정리 ─┴→ 타자 학습 → 완료 카드
   ↑ 두 번째 방문부터: 시작 화면의 "오늘의 복습", "이어서 공부하기"로 바로 학습
```

- 처음 온 사람은 언어 하나 고르고 기본 연습을 누르면 바로 첫 줄을 친다(2단계).
- 친구는 처음엔 치이카와로 정해 두고, 학습 화면에서 언제든 바꾼다(7.2).
- 휴대폰 키보드 배열은 첫 학습 때 10초 확인으로 정한다(11.5).

### 7.1 시작
처음 방문과 다시 방문을 다른 화면으로 보여 준다(와이어프레임 01·M01, 01-B·M01-B). 처음 온 사람에게 빈 "복습·이어서" 칸을 보여 주지 않는다.

**처음 방문 — 5초 안에 "무엇을 하는 곳이고, 뭘 누르면 되는지" 알게 한다**
- 머리글: 로고 "언어 1급" 옆에 "외국어 타자 연습"을 작게 붙인다. 이름만으로는 무슨 사이트인지 모르기 때문이다.
- 제목은 하는 일을 그대로 말한다: "좋아하는 영상 대사를 따라 치며 외국어 타자를 익혀요." 부제: "어떤 키를 누르는지 하나하나 알려 줘요. 휴대폰에서도 돼요."
- **언어 카드가 곧 시작 버튼이다.** "배울 언어를 누르면 바로 시작해요" 아래 5개 카드(6장 순서·표기)를 누르면 바로 재료 화면(기본 연습 탭)으로 간다. 따로 "시작하기" 버튼을 두지 않는다.
- PC 오른쪽(휴대폰은 언어 아래 한 줄)에 "이렇게 연습해요": 실제 학습 화면을 작게 줄인 미리보기(원문·읽기·뜻·노란 키 안내)와 3단계(대사를 듣고 → 따라 치고 → 단어를 담아요).
- "로그인 없이 바로 써요. 기록은 이 브라우저에만 저장돼요." 한 줄.
- 개발자 표시는 맨 아래 오른쪽에 작게.

**다시 방문 — 할 일부터**
- 제목: "다시 왔네요! 오늘도 한 줄씩 쳐 봐요."
- 주요 버튼은 **오늘의 복습**(검정 채움): 틀렸던 줄과 담은 단어 중 오늘 다시 볼 것 5개(약 3분). 다시 보는 때는 1일 → 3일 → 7일 뒤. 맞히면 다음 간격으로, 틀리면 1일로 돌아간다.
- 그 아래 **이어서 공부하기**(마지막 연습, 진도), **저장한 영상**(언어별 개수, 누르면 유튜브 탭의 저장함), 그 아래 "다른 언어로 시작하기" 카드.
- 복습할 것이 없으면 이어서 공부하기가 주요 버튼이 된다.

**공통**
- 상단: 이용 안내, 설정.
- 개발자 표시: 시작 화면 맨 아래 작게 "개발자: 진미리", 이용 안내 맨 아래 "개발자: 진미리 · 개인 공부와 수업용으로 만든 비공식 팬 사이트예요." 학습 화면에는 넣지 않는다.

### 7.2 친구 바꾸기
- 첫 흐름에는 넣지 않는다. 처음엔 치이카와가 함께한다.
- 학습 화면의 친구 옆 "친구 바꾸기"(PC), 상단 친구 얼굴(휴대폰), 설정에서 연다.
- 8명(치이카와, 하치와레, 우사기, 모몽가, 쿠리만쥬, 시사, 랏코, 카니). PC 4열 × 2행, 모바일 2열 × 4행. 고르면 기본 자세와 짧은 말풍선, 시간별 반응 예시를 보여 준다.
- 바꿔도 진도와 누적 시간은 그대로다. 마지막 친구를 기억한다.
- 말투와 문구는 `docs/캐릭터-말투.md`를 따른다.

### 7.3 재료 고르기 — 기본 연습 (채팅 표현)
- 재료 화면의 첫 탭이다. 처음 온 사람의 기본 선택이다.
- 언어마다 같은 4세트: 인사와 대답, 약속 잡기, 리액션, 마무리 인사. 세트마다 10줄 안팎, 3~4분.
- 문장은 직접 쓴다(저작권 문제 없음). 친구와 채팅할 때 실제로 쓰는 짧은 말 위주로 고르고, 원문·발음·한국어 뜻을 미리 검수해 둔다. 이 문장들은 자동 생성이 아니라 고정 자료라서 키보드 안내 검증에도 쓴다.
- 고른 세트는 바로 학습으로 간다(확인·정리 단계 없음).

### 7.4 재료 고르기 — 유튜브
- 유튜브처럼 생긴 화면이다. 상단에 입력창 하나(검색어를 치면 검색, 유튜브 링크를 붙이면 그 영상), 그 아래 언어별 태그(노래, 동요, 드라마, 영화, 예능, 뉴스, 일상·브이로그).
- 태그를 누르면 그 언어로 된 검색어로 검색한다(예: 일본어 + 노래 → `歌 歌詞`, 중국어 + 동요 → `儿歌`). 태그별 검색어는 언어마다 정해 둔다.
- 검색은 자막이 있는 영상으로 거른다. 결과 카드에는 썸네일, 제목, 길이, 채널을 보여 준다.
- 영상을 고르면 자막을 가져와 확인한다(8장). 결과에 따라 이렇게 표시한다.
  - `원문 + 한국어 자막 있음`: 바로 연습할 수 있다.
  - `원문만 있음 → 한국어 자동 번역`: 연습할 수 있고, 뜻에 "자동 번역" 표시를 붙인다.
  - `이 언어 자막 없음` / `외부 재생 막힘`: 연습할 수 없다. 이유를 알리고 비슷한 영상이나 대본 넣기를 권한다.
- 오늘 검색 한도를 다 쓰면 "오늘 검색은 끝났어요. 링크 붙여넣기와 대본은 계속 쓸 수 있어요"라고 알린다. (유튜브 공식 API의 무료 한도는 하루 10,000점, 검색 1번에 100점이라 사이트 전체에서 하루 약 100번이다. 링크 붙여넣기·저장한 영상·이미 연 영상은 한도를 쓰지 않는다. 태그 검색 결과는 1시간 캐시한다. 부족하면 구글에 무료 한도 증가를 신청한다.)
- **영상 저장(유튜브 "저장"처럼):** 영상 카드 썸네일 오른쪽 위, 고른 영상 시트, 학습 화면 머리글에 저장 버튼(책갈피 아이콘 + 글자)을 둔다. 저장한 영상은 태그 줄 맨 앞 "저장한 영상 n" 버튼으로 모아 본다. 이 기기 브라우저에 저장되고 백업 파일에 포함된다. 저장 목록은 검색 한도를 쓰지 않는다(제목·썸네일·길이를 저장해 둠).

### 7.5 재료 고르기 — 대본
- 큰 붙여넣기 칸과 "파일 올리기" 버튼. 받는 형식은 9장을 따르고, 형식은 자동으로 알아본다(형식 고르는 탭 없음).
- 제목 입력(비우면 파일 이름이나 첫 줄로 정한다).
- 유튜브 링크를 함께 넣을 수 있다. 대본에 밀리초 단위 시간이 있으면 영상과 맞춰 구간 재생을 한다.
- **넷플릭스 추천:** 대본 탭 오른쪽(휴대폰은 아래)에 "일본어로 볼 만한 넷플릭스 작품"을 보여 준다.
  - 넷플릭스는 공개 API가 없다. TMDB API의 Discover로 찾는다: 넷플릭스(제공사 8) + 시청 지역 한국(`watch_region=KR`) + 원래 언어(en, ja, zh, mn; 대만어는 `zh` + 제작 국가 TW, 중국어 (간체)는 `zh` + 제작 국가 CN) + 인기순. 드라마와 영화 둘 다.
  - 카드: 포스터, 한국어 제목, 연도, 드라마/영화. 누르면 넷플릭스에서 그 제목을 찾는 새 탭을 연다. 직접 고른 학습 추천 작품에는 "일상 대화 많음" 같은 짧은 표시를 단다(`src/content/netflixPicks.ts`).
  - 결과가 없으면(몽골어 가능성 큼) "지금 한국 넷플릭스에는 몽골어 작품이 거의 없어요"와 함께 유튜브 탭으로 가는 버튼을 보여 준다.
  - 중계 함수가 하루 한 번 받아 저장해 두고 그대로 준다. TMDB 표시 문구(“This product uses the TMDB API but is not endorsed or certified by TMDB.”)를 이용 안내에 넣는다.
  - 조건을 함께 건 검색이 실제로 맞게 나오는지는 단계 0에서 확인한다.

### 7.6 나눈 결과 확인·정리
- 제목은 "24줄로 나눴어요 · 2줄만 확인하면 바로 연습할 수 있어요"처럼 해야 할 일을 말한다.
- 보기 전환: 전체 / 확인 필요(읽기 불확실, 뜻 없음 등)만.
- 나눈 줄을 표로 보여 준다(선택 / 번호 / 시간 / 원문 / 읽기 / 뜻). 문제는 그 칸 아래에 ⚠ 한 줄로 알린다.
- 줄을 체크하면 아래 도구 줄이 켜진다: 위 줄과 합치기, 둘로 나누기, 뜻 한 칸 당기기·밀기, 삭제. 칸을 누르면 그 자리에서 고친다. 버튼을 줄마다 늘어놓지 않는다.
- 뜻 열만 한 칸 위·아래로 밀기(번역이 밀린 대본 대응).
- 영상이 있으면 줄의 시작·끝 시간을 0.1초 단위로 당기거나 밀고, 그 자리에서 들어 볼 수 있다.
- 지운 소리 표시(`[sighs]` 등)는 줄 옆에 작게 보여 주고 되살릴 수 있다.
- 유튜브 자막은 이 단계를 기본으로 건너뛰고 바로 학습으로 가며, 학습 화면에서 언제든 들어올 수 있다. 대본은 이 단계를 거친다.

## 8. 유튜브 자막 가져오기 (중계 함수)

**구성**
- Cloudflare Workers에 중계 함수 하나를 둔다. 하는 일은 셋이다.
  1. 검색: YouTube Data API `search.list`(자막 있는 영상만). 무료 할당량은 하루 약 100회 검색이다.
  2. 자막: 외부 자막 가져오기 서비스(SearchAPI, Apify, ScrapingDog 등 중 시험 후 하나)로 영상 언어 자막과 한국어 자막을 받는다.
  3. 번역: 한국어 자막이 없으면 번역 API(Google Cloud Translation 등, 무료 한도 안)로 채운다.
- 같은 영상을 다시 부르면 저장해 둔 결과를 쓴다(Workers KV 등). 서비스 호출과 비용을 줄이기 위해서다.
- 하루 호출 상한을 둔다. 넘으면 7.3의 한도 안내를 보여 준다.

**자막 정리**
- 사람이 만든 자막을 자동 생성 자막보다 우선한다.
- 자동 생성 자막은 문장부호 없이 잘게 끊겨 온다. 시간 간격과 길이를 기준으로 연습하기 알맞은 줄(대략 2~12초)로 합친다.
- 원문 줄과 한국어 줄은 시간이 겹치는 정도로 짝짓는다.
- 발음과 키보드 안내는 대본과 같은 방식으로 화면에서 만든다(11·12장).

**선행 시험 (만들기 전에 반드시)**
- 언어마다 영상 3개 이상(사람 자막 / 자동 자막 / 노래)으로 자막 서비스 후보를 시험한다.
- 확인할 것: 원문을 받는지, 한국어(번역 자막)를 받는지, 시간이 정확한지, 실패율, 무료 한도와 초과 요금.
- 몽골어는 유튜브 자막이 드물 수 있다. 그러면 몽골어는 대본 위주로 안내한다.
- 시험 결과로 서비스를 정하고 이 장을 고친다.

## 9. 대본 가져오기

**받는 형식**
1. 표 붙여넣기: 탭으로 구분된 `시간 / 원문 / 번역` 또는 `원문 / 번역`(Language Reactor 류 내보내기).
2. CSV / TSV 파일.
3. SRT / VTT: 이중 언어 SRT 하나, 또는 원문 SRT + 한국어 SRT 두 파일을 시간으로 합치기.
4. PDF: 브라우저에서 글자를 뽑아(`pdf.js`) 표나 일반 글로 해석한다. 칸이 섞이기 쉬우므로 7.5 확인을 꼭 거친다.
5. 일반 글: 한 줄에 한 문장. 원문 줄 다음에 한국어 줄이 오는 번갈아 쓰기도 받는다.

**자동 판별**
- 한글이 대부분인 쪽은 뜻, 고른 언어의 문자가 대부분인 쪽은 원문으로 본다. 7.6에서 바꿀 수 있다.
- 시간(`3:01`, `00:03:01,000`, `30s`)은 저장한다. 영상 구간 재생에는 밀리초 단위 시간만 쓴다.

**자동 정리**
- 소리 표시(`[sighs]`, `(radio beeps)`)와 줄 앞 화자 이름(`MAN:`)은 연습 원문에서 뺀다.
- `-A? -B.`처럼 두 사람 대사가 한 줄에 있으면 원문과 번역을 대시 기준으로 나눈다. 대시 개수가 다르면 나누지 않는다.
- `NETFLIX PRESENTS`처럼 제목·자막 정보로 보이는 줄은 표시만 한다.
- 원문이 비거나 소리 표시만 남은 줄은 지운다.

**미확정:** 실제로 쓸 내보내기 도구의 파일 견본으로 형식을 확정한다(17장).

## 10. 타자 학습 화면

**구성 (위에서 아래로)**
1. 상단 바: 제목, 진도 `8 / 24줄`, 연습 시간, 담은 단어 수(누르면 단어장), 설정
2. 영상(유튜브 재료일 때). 휴대폰에서 키보드가 올라오면 작은 크기로 줄이거나 숨긴다(소리는 계속 쓴다).
3. 문장 묶음: 원문(크게), 발음, 한국어 뜻. 이전·다음 줄은 흐리게 한 줄씩(PC만).
4. 입력: 원문 위에 겹쳐 보이는 방식(친 글자는 진하게, 남은 글자는 흐리게, 커서 표시). 실제 입력은 숨은 입력창이 받는다.
5. 키보드 안내 패널(11장). 접을 수 있다.
6. 조작: 듣기, 이전 줄, 다음 줄(건너뛰기), 이 줄 담기
7. 친구: PC는 오른쪽 열 맨 위(말풍선·연습 시간·친구 바꾸기), 휴대폰은 상단 바 옆 작은 얼굴. 말풍선은 문장을 가리지 않는다.

**PC 배치:** 가운데 학습 열 하나와 양옆 보조 열(각 약 200px)이다.
- **가운데(눈이 머무는 곳):** 위에서 아래로 영상 → 대사(이전 줄 · 지금 줄 원문·읽기 · 읽기와 뜻 한 줄) → 지금 칠 키 순서 → 키보드 그림. 눈은 위아래로만 움직이고 좌우로 오가지 않는다. 영상이 없으면 대사부터 시작해 같은 순서로 세로 가운데 정렬한다.
- **오른쪽(손이 찾는 곳):** 듣기(다시 듣기·구간 반복·0.75배) → 이 줄(담기·이전 줄·건너뛰기) → 키보드(배열 바꾸기·안내 단계). 이름표로 묶어 찾기 쉽게 한다.
- **왼쪽(곁눈으로 보는 곳):** 친구, 말풍선, 연습 시간, 친구 바꾸기. 시선의 시작점(왼쪽 위)이 아니라 세로 가운데에 두어, 처음 눈에 띄는 것이 대사가 되게 한다.
- **원칙: 함께 보는 것은 붙여 둔다.** 영상과 대사, 지금 칠 글자와 키 안내처럼 같이 봐야 하는 것은 서로 가장 가까이 둔다.

**휴대폰 배치:** 키보드가 올라오면 `visualViewport` 높이에 맞춰 상단 바를 한 줄로 줄인다. 위에서 아래로 영상(작게)·듣기 → 대사 → 입력창 → 안내(한 줄 안내와 작은 배열 그림) → 휴대폰 키보드 순이다. 칠 때 눈은 입력창과 엄지 근처에 머물므로, 안내를 키보드 바로 위에 붙인다. 틀린 이유도 이 안내 자리에 나온다. 키보드 안내는 기본으로 "한 줄 안내"(11장)만 보이고, 펼치면 작은 배열 그림이 나온다.

**듣기**
- 유튜브 재료: 지금 줄 구간만 재생하고 멈춘다(공식 IFrame Player API). 다시 듣기, 0.75배속.
- 대본·기본 연습(영상 없음): 음성 합성으로 지금 줄을 읽는다. 유튜브와 같은 조작을 둔다: 다시 듣기, 0.75배, 구간 반복(이 줄 반복).
  - **목소리 고르기:** 학습 화면 듣기 버튼 옆 `여자 목소리 ▾`에서 여자/남자를 고른다. 언어마다 기억한다. 설정에도 같은 항목을 둔다.
  - **방식:** Azure 신경망 음성 합성을 중계 함수로 쓴다. 5개 언어 모두 여자·남자 목소리가 있다(몽골어: 여자 Yesui, 남자 Bataa). 목소리 이름은 단계 0 시험에서 언어별로 정한다.
  - **캐시:** 같은 문장·같은 목소리 음성은 한 번 만든 뒤 중계 함수 저장소와 브라우저에 저장한다. 다시 듣기는 저장본을 바로 재생하므로 추가 비용과 기다림이 없다.
  - **대신하기:** 인터넷이 끊기거나 무료 한도를 넘으면 기기 음성(`speechSynthesis`)으로 읽고 "기기 목소리로 읽고 있어요"를 작게 알린다. 기기에 그 언어 음성도 없으면 듣기 버튼을 비활성으로 두고 이유를 알린다.
  - 하루 합성 상한을 중계 함수에 둔다(요금 방지).
- 설정 "줄 시작할 때 자동으로 듣기"(유튜브 기본 켜짐, 대본 기본 꺼짐).

**보기 설정:** 뜻 숨기기, 발음 숨기기, 원문 숨기기(받아쓰기 모드), 키보드 안내 숨기기.

**단축키 (PC):** `Enter` 다음 줄, `Ctrl+Space` 듣기, `Ctrl+←/→` 이전·다음 줄, `Ctrl+S` 이 줄 담기. 입력기와 충돌하면 바꾼다.

## 11. 판정과 키보드 안내

### 11.1 판정
- 확정된 글자만 비교한다. 입력기 조합 중(`compositionstart`~`compositionend`)인 글자에는 오답을 표시하지 않는다.
- 틀린 글자는 그 자리에 물결 밑줄과 빨간 글자로 표시한다(색만으로 구분하지 않는다). 지우고 다시 칠 수 있다.
- **틀린 이유를 말해 준다.** 안내 줄 맨 위에 "✕ б 대신 в를 쳤어요"처럼 무엇이 달랐는지, 그 아래에 맞는 키 위치를 보여 준다. 자주 나는 실수는 이유를 짚는다.
  - 일본어: 탁음 빠짐(`たへ` → "゛가 빠졌어요"), 작은 글자(`つ`/`っ`), 장음, 변환 후보 잘못 고름("다른 한자를 골랐어요: 書く → 描く").
  - 중국어·대만어: 성조 다름(주음), 비슷한 병음(`zh`/`z`, `ü`→`v`), 같은 소리 다른 한자.
  - 몽골어·영어: 옆 키를 누름("в는 아래 줄, б는 가운데 줄이에요").
- 기본은 너그러운 판정이다. 문장부호, 대소문자, 연속 공백, 전각·반각(`，`/`,`), 곧은·굽은 따옴표를 무시하고 자동으로 채운다. 설정 "엄격하게"로 모두 검사한다.
- 일본어는 히라가나·가타카나·한자 중 어떤 것으로 확정해도 읽기가 같으면 맞음으로 칠지 설정한다(기본: 원문과 같은 표기만 맞음, 다른 표기는 "읽기는 맞아요" 안내).
- 줄을 모두 맞게 치면 줄 완료 표시를 하고, `Enter`나 버튼으로 다음 줄로 간다(설정에서 자동 넘김).
- 기록: 줄별 정확도(처음 친 글자 기준), 틀린 줄 목록.

### 11.2 조합 중 글자로 읽기 확인 (핵심)
- 휴대폰 키보드가 어떤 키를 눌렀는지는 사이트가 알 수 없다. 하지만 조합 중인 글자(`compositionupdate`의 내용: 일본어 `たべ`, 주음 `ㄋㄧˇ`, 병음 `nihao`)는 받을 수 있는 경우가 많다.
- 받을 수 있으면 조합 중인 읽기를 기대 읽기와 비교해 "읽기 맞음 / 여기서 틀림"을 보여 주고, 다음 키 안내를 그 위치에 맞춘다.
- 기기·키보드 앱마다 다를 수 있다. 15장에서 검증하고, 받을 수 없는 조합에서는 확정 글자 판정과 순서 안내만 한다.

### 11.3 키보드 안내 — 공통
- 모드는 자동 판별(터치 기기 → 휴대폰)하고, 설정에서 바꿀 수 있다.
- 배열은 6장 표에서 고른다. 처음엔 11.5의 10초 확인으로 정하고 기억한다.
- **학습 중 배열 바꾸기:** 휴대폰 학습 화면의 입력창 옆 버튼(`12키 플릭 ▾`, `주음 ▾` 등), PC 학습 화면의 `PC 로마자 입력 바꾸기`를 누르면 키보드 고르기 시트가 열린다. 바꾸면 안내만 바뀌고 진도는 그대로다.
- **안내가 점점 줄어든다(기본 켜짐):** 같은 글자(또는 같은 키 순서)를 3번 연속 맞게 치면 그 글자는 배열 그림 강조를 빼고 한 줄 안내만, 다시 3번 맞히면 안내 없이 친다. 2초 동안 입력이 없거나 틀리면 그 글자의 안내가 다시 나타난다. 지금 단계는 화면에 `안내 단계: 전체 / 한 줄 / 없음`으로 보여 주고, 설정에서 끌 수 있다.
- **한 줄 안내:** 지금 칠 글자(단어)와 그 입력 순서를 글로 보여 준다. 예: `食べる → たべる → た(た행 탭) べ(は행 → + ゛) る(ら행 ↑) → 변환에서 食べる 선택`.
- **배열 그림:** 고른 배열 그림에서 다음 키를 강조한다. 플릭은 강조한 키 위에 밀 방향 화살표를 띄운다.
- 확신이 낮은 안내(읽기 자동 생성이 불확실한 글자 등)는 숨기거나 "확인 필요"로 표시한다.

### 11.4 키보드 안내 — 언어별
- **영어 쿼티:** 다음 키 강조. 대문자는 Shift도 강조.
- **중국어 병음(PC·휴대폰 쿼티):** 단어 단위로 성조 없는 병음을 차례로 강조(`你好` → `n i h a o`), 이어서 "후보에서 你好 선택(Space 또는 숫자)". `ü`는 `v`로 안내한다.
- **중국어 병음 9키:** 2 ABC, 3 DEF, 4 GHI, 5 JKL, 6 MNO, 7 PQRS, 8 TUV, 9 WXYZ 중 칠 숫자 키를 차례로 강조하고 후보 선택을 안내한다.
- **일본어 PC 로마자:** 읽기를 로마자로 바꿔 강조한다(`た` → `T A`, `っ` → 다음 자음 두 번, `ん` → `N N`). 이어서 "Space로 변환, Enter로 확정".
- **일본어 12키 플릭:** 행 키와 방향을 안내한다(あ단 탭, い단 ←, う단 ↑, え단 →, お단 ↓). 탁음·반탁음·작은 글자는 `゛゜小` 키를 안내한다. 변환 후보 선택까지 안내한다.
- **일본어 12키 탭 반복:** 행 키와 누를 횟수를 안내한다(`う` → あ행 3번).
- **대만 주음(PC):** 표준 大千 배열에서 주음 기호의 키를 차례로 강조하고, 성조 키를 안내한다(1성 Space, 2성 `6`, 3성 `3`, 4성 `4`, 경성 `7`). 이어서 후보 선택.
- **대만 주음(휴대폰):** 휴대폰 주음 자판 그림에서 기호를 차례로 강조하고 성조 키와 후보 선택을 안내한다. 휴대폰 주음 자판 배열은 iPhone·Android에서 확인한 뒤 그린다.
- **몽골어 키릴:** 몽골어 키릴 자판(PC·휴대폰)에서 다음 키를 강조한다. 몽골어 전용 글자(`ө`, `ү`)의 위치를 특히 안내한다. 배열은 기기에서 확인한 뒤 그린다.

### 11.5 키보드 고르기와 10초 확인
- 언제 열리나: 휴대폰에서 그 언어를 처음 연습할 때 자동으로, 이후엔 학습 화면의 배열 버튼과 설정에서.
- 바텀시트 하나에 담는다: 제목 "일본어 키보드 고르기", 설명 "지금 쓰는 휴대폰 키보드와 같아야 안내가 맞아요."
- **10초 확인:** "か를 한 번 쳐 보세요" 같은 글자 하나를 치게 하고, 조합 중 글자(`compositionupdate`)와 입력 이벤트 모양을 보고 배열을 추천한다(예: 가나가 바로 오면 12키, `k`가 먼저 오면 로마자 쿼티). 추천 결과를 목록에 미리 골라 두고 "✓ 12키 플릭으로 보여요"라고 알린다. 판별 규칙은 15장 기기 검증 결과로 정한다. 확신이 없으면 추천하지 않고 직접 고르게 한다.
- **목록:** 그 언어의 배열(6장 표)을 이름과 한 줄 설명으로 보여 준다. 15장 검증 전 배열은 "안내 준비 중"을 붙이고 고를 수는 있게 한다(타자와 채점만).
- 버튼: "이 키보드로 연습"(주요). 시트 바깥을 누르거나 ×로 닫는다.

## 12. 발음(읽기) 만들기

- 모두 화면(브라우저) 안에서 만들고, 7.6에서 고칠 수 있다(기본 연습은 미리 검수한 읽기를 쓴다).
- 중국어: `pinyin-pro`로 성조 병음.
- 대만어 (번체): 병음을 만든 뒤 주음으로 바꾼다. 대만 표준 발음이 본토와 다른 글자(예: 垃圾, 和 등)는 대만 발음 예외표로 보정한다.
- 일본어: 형태소 분석기(`kuromoji` 계열)로 히라가나 읽기를 만들고 로마자로 바꾼다. 사전 파일이 커서 일본어를 고를 때만 불러온다.
- 몽골어: 키릴 문자를 로마자 전사로 바꾼다(전사 규칙 표).
- 영어: 1차에서는 발음 표시 없음.
- 단어 경계는 브라우저 `Intl.Segmenter`(일본어·중국어 단어 단위)로 나눈다.

## 13. 단어·문장 담기와 단어장

- 학습 중 원문 단어를 누르면(클릭·탭) 담는다. "이 줄 담기"로 줄 전체도 담는다.
- 담은 단어는 그 재료의 다른 줄에서도 밑줄로 표시된다. 1차의 "외울 단어 표시"는 이 방식이다.
- 단어 뜻: 직접 적을 수 있다. 중계 함수의 번역으로 자동 제안을 채우고(하루 상한 안), 안 되면 그 줄의 한국어 뜻을 참고로 보여 준다.
- 단어장 패널: 단어, 발음, 뜻, 나온 줄(원문·뜻). 정렬, 삭제.
- 내려받기: TXT(복습용), CSV(단어 / 발음 / 뜻 / 예문 / 예문 뜻, 암기 앱용), "담은 줄만 다시 연습".
- 담은 단어와 틀린 줄은 "오늘의 복습"(7.1)에 들어간다. 복습은 줄을 다시 치는 방식이고, 단어는 그 단어가 나온 줄을 친다.

## 14. 친구(먼작귀)와 시간 보상

- 자료: `chiikawa-language-assets-v3`(8명 × 13포즈 스프라이트 시트, `manifest.json`, `sprites.css`, 시간별 빈 말풍선 SVG).
- 화면에는 시트를 칸으로 자르지 않고, 그림 모양대로 떼어 낸 개별 WebP(8명 × 13장, 320×320, 같은 바닥선)를 쓴다. v3에서 손이 빠진 11칸은 v2 시트의 같은 칸을 써서, 친구마다 13장이 모두 다르다(캐릭터-말투 2-B).
- 실제 연습 시간을 잰다. 탭이 숨겨졌거나 60초 동안 입력이 없으면 멈춘다.
- 0·5·10·…·60분의 13단계. 경계를 넘으면 지금 줄을 마친 뒤 포즈와 말풍선을 바꾼다. 팝업은 없다.
- 30분에는 쉬어 가기를 권하고, 60분에는 축하한다. 60분 이후는 60분 포즈를 유지한다.
- 시간은 재료(연습)마다 누적한다. 친구를 바꿔도 이어진다.
- 말풍선 글은 HTML로 표시하고, 캐릭터 성격에 맞춘 창작 문구를 쓴다(공식 대사를 옮기지 않는다). 캐릭터별 말투 규칙, 상황별 문구, 고르는 규칙은 `docs/캐릭터-말투.md`를 따른다.
- 줄 완료 때 가끔(5줄에 한 번 이하) 짧은 반응을 보인다.
- "캐릭터 움직임 줄이기" 설정. `prefers-reduced-motion`이면 기본으로 켠다.

## 15. 실제 기기 검증 (키보드 안내를 열기 전 필수)

- 기기: iPhone(iOS 기본 키보드) 1대, Android(Gboard) 1대, Windows PC, Mac.
- 배열마다 확인할 것:
  1. 배열 그림과 실제 키 위치가 같은가
  2. 입력 조합 안내대로 치면 원문이 나오는가
  3. `compositionupdate`로 조합 중 글자를 받는가, 받는다면 어떤 형태인가(가나, 주음, 로마자)
  4. 키보드가 올라온 상태에서 문장, 안내, 입력이 보이는가
- 결과를 배열별 표로 남기고, 통과한 배열만 안내를 연다.

## 16. 저장·내보내기·공유

- 자동 저장: 재료(대본·자막), 진도, 단어장, 설정, 누적 시간을 브라우저 저장소(IndexedDB)에 둔다. 같은 기기·브라우저에서만 이어진다.
- 안내: "기록은 이 브라우저에만 저장돼요. 다른 기기로 옮기려면 백업 파일을 내려받으세요."
- 백업: 모든 연습을 `.json`으로 내려받고 다시 올려 복원한다.
- **기록 지키기:**
  - 처음 저장할 때 브라우저에 "이 사이트 기록은 지우지 말아 주세요"를 요청한다(`navigator.storage.persist()`). 거절돼도 동작은 같다.
  - 아이폰 사파리는 7일 동안 안 쓰면 사이트 기록을 지울 수 있다. 사파리에서 처음 쓸 때 한 번 "홈 화면에 추가하면 기록이 더 오래 안전해요"를 알린다(다시 보지 않기 가능).
  - 30줄 이상 쳤는데 백업을 한 번도 안 받았으면, 완료 화면에서 한 번 "백업 파일 받아 두기"를 권한다. 백업 뒤에는 다시 묻지 않는다.
  - 시크릿 모드처럼 저장이 안 되는 환경은 메모리로 동작하고 "이 창을 닫으면 기록이 사라져요"를 알린다.
- 공유(수업용): 연습 하나를 `.json`으로 내보내고, 받은 사람은 "파일 올리기"로 연다. 유튜브 연습은 영상 링크만 담은 짧은 링크로 공유할 수 있다(받은 사람 쪽에서 자막을 다시 가져온다). 짧은 본문(압축 후 약 6,000자 이하)은 링크 주소 `#` 뒤에 담아 공유한다.

## 17. 열린 질문 (만들기 전에 확인)

1. **유튜브 자막 서비스 선택:** 8장 선행 시험으로 정한다. 서비스 가입과 API 키 발급은 사용자가 직접 한다. 같은 방식으로 Azure Speech(음성 합성)와 TMDB 키도 사용자가 직접 발급한다.
2. **대본 견본 파일:** 넷플릭스 이중 자막 내보내기 도구를 다시 확인한다(크롬 주소창 `chrome://extensions`). 그 도구의 견본 파일(PDF 포함 가능)로 9장 규칙과 이용 안내의 "대본 받는 법" 3번을 확정한다.
4. **기본 연습 검수자:** 언어마다 한 명(20.3).
3. **캐릭터 이미지 공개 배포:** 저장소가 공개라 이미지도 공개된다. 배포 전에 이용 조건을 확인하고, 문제가 되면 이미지 없이도 작동하도록 캐릭터 부분을 분리해 둔다.

## 18. 디자인 원칙

참고: 「UI 판단 기준」(디자이너 마디 영상 정리, 2026-10-30). 아래 수치는 와이어프레임 v2에 적용했다.

**걷어내기와 그룹**
- 흰 바탕(#FFFFFF)에 깐다. 회색 배경·카드·박스로 감싸지 않고 여백과 글자 위계로 묶는다. 카드 안에 카드를 넣지 않는다.
- 그룹 안 간격은 좁게, 그룹 사이는 넓게. 구분선은 꼭 필요한 곳에만 1px(#EBEBEB).
- 그림자·그라디언트·글래스는 쓰지 않는다. 바텀시트·서랍만 아주 약한 그림자.

**색**
- 글자색 3단계: #111111(제목·본문) / #505050(보조) / #767676(가장 약한 읽을 글자). #999 이하는 비활성에만. 모두 흰 바탕 4.5:1 이상.
- 포인트 색(버터 노랑 #FFE58A)은 "지금 칠 글자와 지금 누를 키" 한 곳에만 쓴다. 선택 상태는 검정 2px 테두리와 체크로 표시한다.
- 주요 버튼은 검정 채움 하나, 나머지는 외곽선·글자형.
- 상태 글자색: 가능 #1F57E6, 주의(자동 번역·확인 필요) #8A5A00, 성공 #137333, 불가 #767676. 색과 함께 글자·기호(●, ⚠, ✓)로도 구분한다.
- 캐릭터 이미지는 투명 배경 그대로 흰 바탕에 놓는다. 뒤에 색 면을 깔지 않는다.

**글자**
- 웹 본문 16, 보조 14~15, 제목 32(페이지)·20~24(섹션). 모바일 본문 15~16, 보조 14, 배지 최소 12. 11 이하는 쓰지 않는다.
- 굵기는 400과 700 두 가지. 행간 본문 140~150%, 제목 125~135%.
- 글꼴: 한글 Noto Sans KR(구현 시 Pretendard로 바꿔도 된다), 일본어 Noto Sans JP, 간체 Noto Sans SC, 번체 Noto Sans TC, 몽골어 키릴 지원 글꼴. 로고만 둥근 글꼴(Jua).
- 아직 칠 글자는 #767676 보통 굵기로, 친 글자는 #111111 굵게. 아직 칠 글자도 읽을 수 있어야 한다.

**컴포넌트**
- 버튼 높이: 웹 주요 52·보조 44~48, 모바일 주요 52·보조 40~48. 누를 수 있는 것은 최소 44×44.
- 버튼·인풋·탭의 모서리는 12로 통일(칩은 완전히 둥글게).
- 토글 28×52, 체크박스 20.
- 수정·삭제는 줄마다 늘어놓지 않고, 체크 선택 후 아래 도구 줄로 한다.

**흐름**
- 화면마다 가장 중요한 행동 하나(주요 버튼 하나)를 정한다.
- 진행 단계는 상단에 `2 / 3단계`처럼 짧게 보여 준다. 시작부터 첫 줄까지 3단계 안에서 끝낸다.
- 오류·빈 상태는 이유와 다음 행동 두 개(주요·보조)를 함께 보여 준다(10번 화면).
- 휴대폰은 키보드가 올라온다는 전제로 설계한다.
- **애매한 빈 공간을 남기지 않는다.** 내용이 화면보다 짧으면 위아래 가운데로 모아 상하좌우 여백을 고르게 둔다. 버튼은 내용 바로 아래에 붙이고, 화면 맨 아래로 밀어 내용과 버튼 사이가 붕 뜨게 하지 않는다. 바닥 고정 버튼은 휴대폰의 주요 버튼에만 쓴다.
- **가로 스크롤을 만들지 않는다.** 화면 전체는 물론, 태그·칩 줄도 옆으로 밀어야 보이게 하지 않는다. 넘치면 다음 줄로 접는다. 사용자가 숨은 항목을 모르고 지나치기 때문이다.

**사용자 배려 점검표 (화면을 만들 때마다 확인)**
1. 이 화면에서 사용자가 하려는 일이 하나로 분명한가? 주요 버튼이 하나인가?
2. 숨어 있어서 못 찾는 것(가로 스크롤, 작은 아이콘만 있는 버튼, 펼쳐야 보이는 필수 정보)이 없나?
3. 애매한 빈 공간이나, 내용과 버튼 사이가 붕 뜬 곳이 없나?
4. 필요 없는 요소(같은 기능 버튼 두 개, 의미 없는 장식·선·배지, 반복 문구)가 없나?
5. 처음 온 사람도 설명 없이 다음에 뭘 할지 아나? 막히면 바로 옆에 이유와 다음 행동이 있나?
6. 휴대폰에서 키보드가 올라온 상태, 가장 긴 문장, 빈 목록, 오류일 때도 화면이 무너지지 않나?
7. 글자는 충분히 크고(웹 16·휴대폰 15 이상), 누를 곳은 44px 이상인가?
8. 되돌릴 수 있나? 지우기·바꾸기 뒤에 되돌리기가 있나?
- 폭 360px 휴대폰부터 넓은 PC 화면까지 지원하고, 가로 스크롤이 생기면 안 된다.

## 19. 만드는 사람에게 맡기는 것 (작성자 판단)

- 구현 기술: Vite + TypeScript(+ React 또는 바닐라) 권장. GitHub Actions로 Pages에 배포한다. 저장소 하위 경로(`/chiikawa-language-typing/`)에서 이미지와 화면 이동이 깨지지 않아야 한다.
- 태그별 검색어 목록의 세부 문구.
- 자동 생성 자막을 줄로 합치는 세부 규칙.
- 응원 문구의 세부 문장.

## 20. 만드는 순서와 완료 기준

1차 범위에서 빼는 것은 없다. 5개 언어, 기본 연습, 유튜브(검색·링크로 자동 자막), 대본, 친구, 복습, 단어장을 모두 1차에 만든다. 대신 **세로로 자른다**: 한 언어를 처음부터 끝까지 완성한 뒤 다음 언어로 넘어가고, 각 단계가 끝날 때마다 배포 주소에서 실제로 쓸 수 있는 상태를 유지한다. 다섯 언어를 동시에 반쯤 만드는 상태를 만들지 않는다.

**단계 0. 기반과 선행 시험** (계획: `docs/superpowers/plans/2026-11-01-foundation-and-spikes.md`)
- 저장소, Vite + React + TypeScript, GitHub Pages 자동 배포.
- 휴대폰 입력 시험 페이지로 조합 중 글자 받기 확인(15장). 결과로 11.2·11.5장을 확정한다.
- 유튜브 자막 서비스 시험(8장). 결과로 서비스를 고르고 8장을 확정한다. 실패해도 다음 단계는 막히지 않는다(단계 4에서 다른 서비스나 방식으로 다시 시도).
- 음성 합성 시험: 5개 언어 × 여자·남자 목소리 이름, 무료 한도, 응답 속도.
- TMDB 시험: 언어별 넷플릭스·한국 조건 검색 결과 수와 정확도.

**단계 1. 일본어 끝까지** (사용자의 가장 큰 고민) — 1-A 완료(2026-11-01): 일본어 기본 연습 4세트, PC 키 안내, 학습·완료·친구·설정·이용 안내 화면, 저장, 기기 음성. 남은 것: 1-B 중계 함수 목소리(Azure 키 필요), 휴대폰 키 안내 열기(입력 시험 결과 필요).
- 중계 함수의 첫 기능(음성 합성과 캐시), 여자/남자 목소리 듣기·다시 듣기.
- 입력 엔진(판정, 읽기 생성, 12키 플릭·탭·로마자 키 순서), 기본 연습 일본어 4세트, 학습 화면(PC·휴대폰), 키보드 고르기와 10초 확인, 안내 줄이기, 틀린 이유 안내, 완료 카드, 친구(치이카와 기본 + 바꾸기), 말투 문구 전부, 저장.
- 끝나면: 일본어 기본 연습으로 처음 방문부터 완료 카드까지 PC와 휴대폰에서 된다. 배포한다.

**단계 2. 대본 넣기**
- 대본 가져오기(표·CSV·SRT·VTT·PDF·일반 글), 넷플릭스 추천, 확인·정리 화면, 단어 담기, 단어장, 백업·공유, 오늘의 복습, 효과 기록(20.2).
- 끝나면: 일본어 넷플릭스 대본을 넣어 연습하고 단어장을 받는다.

**단계 3. 나머지 4개 언어**
- 대만어 (번체) → 중국어 (간체) → 영어 → 몽골어 순. 언어마다 엔진의 언어 부분, 키보드 배열 데이터, 기본 연습 4세트, 15장 기기 검증을 끝내고 배포한다.

**단계 4. 유튜브**
- 중계 함수(Cloudflare Workers), 검색·태그·링크 하나로 받기, 자동 자막과 한국어, 구간 재생, 한도 안내, 상태 안내 화면.
- 5개 언어 모두 유튜브로 연습할 수 있다(몽골어는 자막 있는 영상이 적으면 그 사실을 화면에서 알린다).

**단계 5. 마무리**
- 사용자 배려 점검표(18장)로 전 화면 점검, 접근성 점검, 성능 점검, README와 화면별 캡처.
- README는 사용자의 Pick & Go README 형식(가운데 정렬 로고·한 줄 소개·기술 배지, 목차 표, 문제–해결 표, 차별점 표, 화면별 캡처, 배포 URL과 실행 방법, 개발 과정·어려웠던 점·배운 점)을 따른다. 캡처는 PC와 휴대폰 모두 실제 배포 사이트에서 찍는다. 기획 과정(유튜브 자막 차단 시험 → 대본 방식 → 두 입구 구조 → 사용성 개선)을 "개발 과정"에 담는다.

### 20.1 완료 기준 (1차 전체)
- 5개 언어 모두 기본 연습, 대본, 유튜브로 연습할 수 있다.
- 처음 온 사람이 언어 선택 → 기본 연습 → 첫 줄 입력까지 두 번 누르면 된다.
- 15장 검증을 통과한 배열에서 키보드 안내가 틀린 키 없이 나온다. 통과 못 한 배열은 "안내 준비 중"으로 표시되고 타자·채점은 된다.
- 휴대폰(iPhone, Android)에서 키보드가 올라와도 원문, 뜻, 한 줄 안내, 입력 상태가 보인다.
- 입력기 조합 중에 오답 표시가 뜨지 않는다. 틀리면 무엇이 달랐는지 알려 준다.
- 키보드 고르기 시트와 10초 확인이 된다. 학습 중에 배열을 바꿔도 진도가 그대로다.
- 안내가 익숙해지면 줄고, 막히면 다시 나온다.
- 5분 단계 반응과 캐릭터 말투가 `docs/캐릭터-말투.md`대로 나오고 입력을 끊지 않는다. 다 마치면 완료 카드가 나온다.
- 오늘의 복습이 1·3·7일 간격으로 나온다. 완료 화면에 지난번과 비교가 나온다.
- 대본·기본 연습에서도 여자/남자 목소리로 듣고 다시 들을 수 있다.
- 대본 탭에서 언어별 넷플릭스 작품 추천이 나온다(없으면 이유와 유튜브 안내).
- 단어를 담아 CSV·TXT로 내려받고, 백업 파일로 복원된다. 새로고침해도 진도가 남아 있다.
- 유튜브 검색·자막 한도를 넘으면 안내가 나오고 요금이 상한을 넘지 않는다.
- 사용자 배려 점검표 8가지를 모든 화면이 통과한다. 가로 스크롤과 애매한 빈 공간이 없다.
- 배포 주소에서 위 흐름이 모두 작동한다.

### 20.2 효과 기준 (이 사이트가 정말 도움이 되나)
- 사이트가 언어별로 "기본 연습 세트의 한 줄 평균 시간"과 "처음 친 글자 정확도"를 날짜별로 기록한다(이 기기 안에만).
- 시작 화면 이어서 공부하기 아래에 작게 "일본어 · 2주 전보다 한 줄 3.1초 빨라졌어요"처럼 보여 준다. 기록이 3번 미만이면 보이지 않는다.
- 만든 사람의 목표: 일본어·대만어 기본 연습 "약속 잡기" 세트를 2주 동안 하루 10분 연습했을 때, 한 줄 시간이 처음보다 30% 줄고 정확도 90% 이상. 2주 뒤 이 숫자로 1차를 평가하고 2차 우선순위를 정한다.

### 20.3 기본 연습 문장 준비와 검수
- 5개 언어 × 4세트(인사와 대답, 약속 잡기, 리액션, 마무리 인사) × 10줄 = 200줄. 세트끼리 같은 뜻으로 맞춰 둔다(언어를 바꿔도 같은 상황을 연습).
- 문장 초안, 읽기(후리가나·주음·병음·로마자 전사), 한국어 뜻은 Claude가 작성하고 사전·표준 표기로 한 번 더 확인한다.
- 검수: 언어마다 원어민 또는 그 언어를 잘하는 사람 한 명에게 세트 4개를 보여 주고 "채팅에서 자연스러운가"만 확인받는다. 검수 전 세트는 화면에 작게 "검수 전"을 붙인다.
- 문장 자료는 `src/content/starter/<언어>.json` 한 파일씩 두고, 고칠 때 이 파일만 바꾼다.

### 20.4 화면·코드 설계
- 프론트 구조, 데이터 모양, 엔진 입출력, 저장 형식, 테스트·성능·접근성 기준은 `docs/프론트-설계.md`를 따른다.
