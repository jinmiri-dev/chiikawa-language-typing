# 언어 1급 — 보안·오류 점검

작성일: 2026년 11월 1일 · 단계마다 갱신한다.
관련: [아키텍처·API·ERD](아키텍처-API-ERD.md) · [프론트 설계](프론트-설계.md)

이 사이트는 로그인과 서버 DB가 없어서 "개인정보 유출"보다는 **중계 함수 남용(요금)**, **사용자가 넣은 파일로 인한 오류·스크립트 실행**, **공급망(의존성)**이 주된 위험이다.

## 2. 오류 대비

| 상황 | 처리 | 상태 |
|---|---|---|
| 모르는 주소 | "페이지를 찾을 수 없어요" + 처음으로 | ✅ |
| 저장소(IndexedDB)를 못 씀(사생활 보호 모드 등) | 메모리로만 동작하고 알림 | ⏳ 단계 1 |
| 브라우저가 기록을 지움(사파리 7일 규칙, 저장 공간 부족) | `navigator.storage.persist()` 요청, 사파리 홈 화면 추가 안내, 백업 권유 | ⏳ 단계 1·2 |
| 화면 하나가 오류 | 화면 단위 Error Boundary: "다시 시도 / 처음으로", 학습 기록은 줄마다 저장 | ⏳ 단계 1 |
| Worker 실패·한도 초과 | 상태 안내(와이어프레임 10번), 기본 연습·대본은 계속 | ⏳ 단계 1·4 |
| 오프라인 | 저장한 연습은 계속, 듣기는 기기 음성 | ⏳ 단계 5 |

## 3. 단계마다 하는 점검

1. `npm audit`, `npm run lint`, `npm test`, `npm run build` (CI가 자동으로 함)
2. 저장소 검색: 키·비밀값·개인 파일(`.pdf`, `.zip`, `.env`)이 없는지
3. 위험한 코드 검색: `innerHTML`, `dangerouslySetInnerHTML`, `eval`, `new Function`
4. 빌드본을 띄워 콘솔 오류·CSP 위반이 0개인지
5. 5개 언어 모두 해당 단계 기능이 되는지

## 5. 전체 점검 (2026-11-05, OWASP Top 10:2025 기준)

이 사이트는 직접 운영하는 리눅스 서버가 없다(화면: GitHub Pages, 중계: Cloudflare Worker). 그래서 SSH·방화벽·fail2ban 같은 서버 점검 대신 아래를 본다.

| 번호 | 항목 | 지금 상태 | 위험도 | 조치 |
|---|---|---|---|---|
| A01 | 접근 제어 | 로그인·관리 화면 없음. 중계 서버 키 쓰는 경로는 허용 출처에서만 | 낮음 | 출처(Origin) 없는 요청도 403(목소리만 예외) |
| A02 | 보안 설정 | 화면 CSP(빌드 때 주입), HTTPS 강제. GitHub Pages 는 응답 헤더를 못 붙임 | 낮음 | 중계 응답에 nosniff·no-referrer·CSP(frame-ancestors none), 화면은 iframe 안에서 열리면 빠져나옴 |
| A03 | 공급망 | `npm audit` 0건, Actions 커밋 해시 고정, Dependabot·CodeQL | 낮음 | 그대로 |
| A04 | 암호화 | 모든 통신 HTTPS, 키는 Worker 비밀값에만. 저장소 이력·빌드본에서 키 0건 | 낮음 | 그대로 |
| A05 | 인젝션 | 화면은 글자로만 그림(innerHTML·eval 0건), 중계는 주소 매개변수로만 바깥 API 호출 | 낮음 | 그대로 |
| A06 | 안전하지 않은 설계 | 하루 전체 상한만 있어 한 사람이 자막 서비스 무료 횟수를 다 쓸 수 있었음 | 중간 → 낮음 | 한 사람(IP) 하루 상한 추가(검색 30, 자막 25, 넷플릭스 20, 목소리 5,000자), IP 는 해시만 |
| A07 | 인증 | 사이트 로그인 없음. 계정은 GitHub·Cloudflare·Google·SearchAPI·TMDB | 확인 필요 | 각 계정 2단계 인증(직접) |
| A08 | 무결성 | 백업·공유 파일은 형식 검사 뒤에만 저장 | 중간 → 낮음 | 공유 조각 모양·원문 일치 검사, 줄 수·길이 상한, 백업 설정은 아는 항목·맞는 모양만 |
| A09 | 로깅·경보 | 중계 서버는 바깥 서비스 오류 코드를 남김(wrangler tail) | 낮음 | Cloudflare 대시보드 알림(선택) |
| A10 | 예외 처리 | 화면 오류 경계, 중계는 알 수 없는 오류를 일반 문구로 | 낮음 | 그대로 |

오래 쓰기: 화면 120번 오가기·80줄 연속 타자에서 오류 0, 메모리 늘지 않음, 저장 공간 +4KB. 없는 캐릭터 그림을 화면마다 다시 받아 404 가 쌓이던 것은 한 번만 받게 고침.

사이트를 남이 베끼는 것: 화면 코드는 공개 저장소(무료 GitHub Pages 조건)라 기술로 막을 수 없다. LICENSE 로 모든 권리 보유를 밝혔고, 비용이 드는 키는 중계 서버에만 있어 베껴 가도 키는 쓸 수 없다.

## 6. 무료 자막 길 추가 점검 (2026-11-06)

- 바깥으로 나가는 것: 중계 서버가 LRCLIB 에는 영상 제목에서 뽑은 노래·가수 이름만, Workers AI 에는 자막·가사 줄만 보낸다. 사용자 기록·IP·키는 보내지 않는다.
- 엉뚱한 가사 막기: 노래 이름과 가수 이름이 제목·채널에 모두 있고, 길이가 영상과 맞고, 그 언어 글자일 때만 쓴다(예고편·동화가 같은 이름 노래와 짝지어지지 않게, 시험 있음).
- 느린 바깥 서비스: LRCLIB 요청은 7초에 끊고, AI 호출은 한 요청에 정해진 횟수 안에서만(무료 요청 수 상한 50 안). 실패하면 뜻 없이도 열리고 다음 날 다시 번역한다.
- 사용량: 새 영상 자막은 하루 300·한 사람 40으로 묶는다. AI 무료 사용량을 넘겨도 카드가 없어 요금은 나오지 않는다.
- 브라우저: 키보드 자동 인식은 입력기 조합 글자와 누른 키만 그 자리에서 보고 저장·전송하지 않는다.
