# 언어 1급 — 프론트 설계서

작성일: 2026년 11월 1일
기획안 v4(`docs/기획안.md`)를 코드로 옮길 때의 구조와 약속이다. 화면은 와이어프레임 v3(https://claude.ai/artifact/GCFCH4CsMJLgiCPTCoxgX3), 캐릭터 문구는 `docs/캐릭터-말투.md`를 따른다.

## 1. 기술 선택

| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite + React 18 + TypeScript | 정적 배포, 빠른 개발 |
| 라우팅 | 해시 라우팅(직접 구현, `#/...`) | GitHub Pages 하위 경로에서 새로고침해도 안전 |
| 상태 | React Context + `useReducer` (화면 상태), 저장소 모듈(영속 상태) | 라이브러리 최소화 |
| 저장 | IndexedDB (`idb` 라이브러리) | 대본·기록이 커질 수 있음 |
| 중국어 읽기 | `pinyin-pro` | 성조 병음, 다음음자 처리 |
| 일본어 읽기 | `kuromoji` 계열 + 사전 파일 | 일본어를 고를 때만 불러옴 |
| PDF | `pdfjs-dist` | PDF를 올릴 때만 불러옴 |
| 공유 링크 압축 | `lz-string` | 짧은 본문을 링크에 담기 |
| 단어 경계 | 브라우저 `Intl.Segmenter` | 추가 용량 없음 |
| 유튜브 재생 | 공식 IFrame Player API | 유튜브 연습을 열 때만 불러옴 |
| 유튜브 검색·자막, 음성 합성, 넷플릭스 추천 | 중계 함수(Cloudflare Workers, 저장소의 `worker/`): 유튜브 자막 서비스, Azure Speech, TMDB | API 키를 화면 코드에 두지 않음 |
| 듣기 | `services/speech`: 중계 함수 음성(캐시) → 실패 시 기기 `speechSynthesis` | 남녀 목소리를 모든 기기에서 같게 |
| 테스트 | Vitest + Testing Library(단위·화면), Playwright(PC·휴대폰 크기 흐름) | |
| 품질 | ESLint, Prettier, TypeScript strict | |

## 2. 폴더 구조

```
src/
  app/            App, 라우터, 전역 Provider, 레이아웃(헤더)
  screens/        화면 하나에 폴더 하나 (Home, Materials, Review, Study, Done, Friend, Settings, Guide, Lab)
  components/     여러 화면이 쓰는 부품 (Button, Chip, Toggle, Sheet, Drawer, Ruby, KeyboardMap, FriendBubble, StatusNotice)
  engine/         화면과 무관한 순수 로직 (테스트 대상의 대부분)
    judge/        판정, 틀린 이유
    reading/      언어별 읽기 생성
    layouts/      키보드 배열 데이터와 키 순서 계산
    hint/         안내 단계(줄이기) 계산
    review/       복습 일정
    import/       대본 가져오기(형식 판별, 정리)
    stats/        효과 기록 계산
  services/       바깥과 닿는 부분 (storage, youtube, speech, files)
  content/        고정 자료 (starter/<lang>.json, friendLines.ts, tags.ts)
  styles/         tokens.css, base.css
worker/           Cloudflare Workers 중계 함수 (/search, /transcript, /tts, /netflix)
public/           캐릭터 이미지(WebP), 일본어 사전, manifest
```

규칙: `engine/`은 React와 브라우저 저장소를 모른다. 화면은 `engine/`과 `services/`를 부르기만 한다.

## 3. 화면과 라우트

| 라우트 | 화면 | 와이어프레임 |
|---|---|---|
| `#/` | 시작(언어 고르기, 오늘의 복습, 이어서) | 01, M01 |
| `#/materials?lang=ja&tab=starter` | 재료 고르기(기본 연습·유튜브·대본 탭) | 02-A/B/C, M02 |
| `#/review/:materialId` | 나눈 결과 확인(대본만) | 03 |
| `#/study/:materialId` | 타자 학습 | 04, M04 |
| `#/done/:materialId` | 완료 카드 | 05, M05 |
| `#/friend` | 친구 바꾸기 | 07 |
| `#/settings` | 설정 | 08 |
| `#/guide` | 이용 안내 | 09 |
| `#/lab/input` | 입력 시험(개발용, 메뉴에 없음) | — |

- 키보드 고르기 시트(M03)와 단어장 서랍(06)은 라우트가 아니라 화면 위에 여는 층이다. 열 때 `history.pushState`로 한 칸을 쌓아, 휴대폰 뒤로 가기가 층만 닫게 한다.
- 시작 화면에서 언어를 고르면 `#/materials?lang=…`로 간다. 친구 선택은 흐름에 없다.

## 4. 데이터 모양

```ts
type Lang = 'en' | 'ja' | 'zh' | 'tw' | 'mn';   // 화면 순서도 이 순서
type FriendId = 'chiikawa' | 'hachiware' | 'usagi' | 'momonga' | 'kurimanju' | 'shisa' | 'rakko' | 'kani';
type LayoutId =
  | 'en-qwerty'
  | 'ja-pc-romaji' | 'ja-flick' | 'ja-tap' | 'ja-mobile-romaji'
  | 'zh-pinyin' | 'zh-pinyin-9key'
  | 'tw-zhuyin-pc' | 'tw-zhuyin-mobile' | 'tw-pinyin'
  | 'mn-cyrillic';

interface Material {
  id: string;
  lang: Lang;
  kind: 'starter' | 'youtube' | 'script';
  title: string;
  youtubeId?: string;          // youtube, 또는 대본에 링크를 넣었을 때
  koSource: 'given' | 'youtube' | 'auto' | 'none';  // 뜻이 어디서 왔나 (화면 표시용)
  lines: Line[];
  createdAt: number;
}

interface Line {
  id: string;
  src: string;                 // 연습할 원문 (소리 표시 제거 후)
  ko?: string;                 // 한국어 뜻
  start?: number; end?: number;// 초, 영상 구간
  segments: Segment[];         // 읽기와 단어 경계
  removed?: string[];          // 지운 소리 표시 (되살리기용)
  needsCheck?: ('reading' | 'ko')[];
}

interface Segment {
  text: string;                // 원문 조각 (예: 食べ)
  reading?: string;            // ja: ひらがな, zh/tw: 성조 병음, tw는 zhuyin도
  zhuyin?: string;
  romaji?: string;             // ja 로마자, mn 로마자 전사
  isWord: boolean;             // 단어 시작 여부(담기·밑줄용)
  confident: boolean;          // 읽기 확신. false면 안내를 숨기거나 "확인 필요"
}

interface LineResult { lineId: string; firstTryAccuracy: number; ms: number; mistakes: number; at: number }
interface Progress { materialId: string; lineIndex: number; results: LineResult[]; activeMs: number; friend: FriendId }

interface Word { id: string; lang: Lang; text: string; reading?: string; meaning?: string; from: { materialId: string; lineId: string } }
interface ReviewItem { id: string; ref: { materialId: string; lineId: string }; due: number; step: 0 | 1 | 2 | 3 }  // 0:1일 1:3일 2:7일 3:졸업

interface Settings {
  device: 'auto' | 'pc' | 'mobile';
  layout: Partial<Record<Lang, LayoutId>>;
  hintMode: 'full' | 'line' | 'off';
  hintFading: boolean;
  show: { ko: boolean; reading: boolean; src: boolean };
  strict: boolean;
  autoListen: boolean;
  reduceMotion: boolean;
  voice: Partial<Record<Lang, 'female' | 'male'>>;  // 기본 'female'
  rate: 1 | 0.75;
  friend: FriendId;            // 기본 'chiikawa'
}
```

## 5. 엔진의 입출력 (모두 순수 함수, 단위 테스트 필수)

```ts
// reading/ — 원문을 조각과 읽기로
buildSegments(lang: Lang, text: string): Promise<Segment[]>

// layouts/ — 배열 데이터와 키 순서
interface KeyDef { id: string; label: string; row: number; col: number; w?: number; flick?: Partial<Record<'left'|'up'|'right'|'down', string>> }
interface Layout { id: LayoutId; lang: Lang; device: 'pc' | 'mobile'; rows: KeyDef[][]; verified: boolean }
interface KeyStep { keyId: string; gesture?: 'tap' | 'left' | 'up' | 'right' | 'down'; taps?: number; text: string }
keySteps(layout: Layout, seg: Segment): { steps: KeyStep[]; convert?: string; confident: boolean }
// 예: ja-flick, べ → [{keyId:'ha', gesture:'right', text:'へ'}, {keyId:'dakuten', gesture:'tap', text:'゛'}]

// judge/ — 판정
judge(expected: string, committed: string, opts: { strict: boolean; lang: Lang }): { okUpTo: number; wrongAt?: number; done: boolean }
explainMistake(lang: Lang, expected: string, typed: string, layout?: Layout): string | null
// 예: ('ja','たべ','たへ') → '゛가 빠졌어요', ('mn','б','в') → 'б 대신 в를 쳤어요'

// 조합 중 글자
readingProgress(lang: Lang, expectedReading: string, composing: string): { matches: boolean; at: number }

// hint/ — 안내 줄이기
nextHintLevel(state: HintMemory, unitKey: string, correct: boolean, idleMs: number): 'full' | 'line' | 'off'

// review/
schedule(item: ReviewItem, correct: boolean, now: number): ReviewItem
dueToday(items: ReviewItem[], now: number, max = 5): ReviewItem[]

// import/ — 대본
detectFormat(input: string | File): Promise<'table' | 'csv' | 'srt' | 'vtt' | 'pdf' | 'text'>
parseScript(input: string | File, lang: Lang): Promise<{ lines: Line[]; removedCount: number; checkCount: number }>

// stats/
lineSpeedTrend(results: LineResult[], days: number): { before: number; after: number } | null
```

- 키보드 배열은 코드가 아니라 데이터(`engine/layouts/data/<layoutId>.ts`)다. 배열을 고치거나 추가할 때 데이터만 바꾼다. `verified: false`인 배열은 안내를 보이지 않는다.
- 언어별 차이는 `engine/*/<lang>.ts`로 나누고, 공통 함수가 언어 모듈을 고른다.

## 6. 저장과 백업

- IndexedDB 데이터베이스 `language-grade1`, 저장소: `materials`, `progress`, `words`, `review`, `stats`, `settings`. 스키마 버전 1부터, 바꿀 때마다 올리고 이전 버전 변환 함수를 둔다.
- 저장이 안 되는 환경(사생활 보호 모드 등)에서는 메모리로만 동작하고, 시작 화면에 "이 브라우저에서는 기록이 저장되지 않아요"를 알린다.
- 백업 파일: `language-grade1-backup-YYYYMMDD.json`
  ```json
  { "app": "language-grade1", "version": 1, "exportedAt": "…", "data": { "materials": [], "progress": [], "words": [], "review": [], "stats": [], "settings": {} } }
  ```
  불러올 때 버전을 확인하고, 같은 id는 "덮어쓰기 / 둘 다 두기"를 묻는다.
- 공유 파일은 `Material` 하나만 담는다. 짧으면 `#/share/<lz-string>` 링크로도 준다(약 6,000자 이하).

## 7. 휴대폰 키보드 대응

- `window.visualViewport`의 `resize`를 듣고 CSS 변수 `--vvh`에 실제 보이는 높이를 넣는다. 학습 화면 높이는 `var(--vvh)`로 잡는다.
- 입력창은 원문 바로 아래·키보드 바로 위에 오게 하고, 포커스 때 `scrollIntoView({ block: 'nearest' })`.
- 입력창 글자 크기는 16px 이상(iOS 자동 확대 방지). `autocomplete="off" autocorrect="off" autocapitalize="off" spellcheck="false"`.
- 판정은 `compositionend`와 `input`(조합 중이 아닐 때)에서만 한다. 조합 중에는 `compositionupdate`로 읽기 진행만 본다.
- 실제 입력창은 화면에 보이는 입력 줄 그 자체다(숨은 입력창 + 그림 겹치기는 휴대폰 커서·선택 문제가 있어 쓰지 않는다). PC 학습 화면도 같은 방식으로 통일한다.

## 9. 성능 기준

- 첫 화면 JS(압축 후) 150KB 이하. 일본어 사전, PDF, 유튜브 플레이어, 언어별 글꼴은 그 기능을 쓸 때 불러온다.
- 글꼴: Noto Sans KR은 처음부터, Noto Sans JP/SC/TC는 그 언어를 고를 때 불러온다.
- 캐릭터 시트는 WebP로 바꾸고 한 장 300KB 이하. 지금 친구 시트만 불러온다.
- 휴대폰 4G 기준 첫 화면 2.5초 안에 보이고, 타자 입력에서 화면 반응 50ms 안.

## 10. 접근성

- 키보드만으로 모든 화면을 쓸 수 있다. 포커스 표시를 지우지 않는다.
- 판정 결과("맞았어요", "б 대신 в를 쳤어요")와 친구 말은 `aria-live="polite"`로 읽힌다. 키 안내는 화면 읽기에서 "다음: は 키를 오른쪽으로"처럼 문장으로 읽힌다.
- 색만으로 구분하지 않는다(물결 밑줄, ✓, ✕, ⚠). 대비 4.5:1(토큰으로 보장).
- `prefers-reduced-motion`이면 캐릭터 움직임 줄이기를 켠다.
- 외국어 원문에는 `lang` 속성(ja, zh-CN, zh-TW, mn)을 붙여 글꼴과 읽기가 맞게 한다.

## 11. 테스트

- **엔진 단위 테스트:** 기본 연습 200줄 전부를 고정 자료로 써서, 줄마다 읽기와 배열별 키 순서가 "정답 표"와 같은지 검사한다. 정답 표는 15장 기기 검증 때 실제로 쳐 본 결과로 만든다.
- **판정 테스트:** 조합 중 오답 없음, 너그러운 판정(문장부호·전각·따옴표), 엄격 모드, 틀린 이유 문구.
- **가져오기 테스트:** 견본 대본(표, CSV, SRT, VTT, PDF, 일반 글)마다 줄 수, 소리 표시 제거, 두 사람 대사 나누기.
- **화면 흐름 테스트(Playwright):** PC 1280×800, 휴대폰 360×780·390×844에서
  - 처음 방문 → 언어 → 기본 연습 → 첫 줄 완료 → 완료 카드
  - 대본 붙여넣기 → 확인 → 연습 → 단어 담기 → CSV 받기 → 백업 → 복원
  - 모든 라우트에서 가로 스크롤 없음(`document.documentElement.scrollWidth <= innerWidth`)
  - 조합 이벤트를 흉내 내 보내서 조합 중 오답이 안 뜨는지
- **사람이 하는 점검:** 단계가 끝날 때마다 사용자 배려 점검표 8가지(기획안 18장)와 실제 iPhone·Android에서 입력.

## 11-B. 중계 함수 엔드포인트

| 경로 | 입력 | 출력 | 캐시 |
|---|---|---|---|
| `GET /search` | `q`, `lang`, `tag` | 영상 목록(자막 있는 것만) | 1시간 |
| `GET /transcript` | `v`, `lang` | 원문 줄과 한국어 줄(시간 포함), 출처(사람/자동/번역) | 영상별 30일 |
| `GET /tts` | `lang`, `voice`(female/male), `text` | 음성 파일(mp3) | 문장·목소리별 영구 |
| `GET /netflix` | `lang` | 작품 목록(TMDB) | 하루 |

- 모든 경로에 하루 상한을 두고, 넘으면 `429`와 남은 시간을 돌려준다. 화면은 상태 안내(와이어프레임 10번)를 보여 준다.
- 허용 출처는 배포 주소와 로컬 개발 주소만.

## 12. 오류와 오프라인

- 유튜브 중계 함수가 실패하거나 한도에 걸리면 재료 화면이 상태 안내(와이어프레임 10번)를 보여 주고, 기본 연습·대본은 그대로 쓸 수 있다.
- 인터넷이 끊겨도 이미 저장한 연습은 계속 칠 수 있다(앱 화면과 기본 연습은 캐시).
- 화면 오류는 화면 단위로 막아(Error Boundary) "다시 시도 / 처음으로"를 보여 준다. 학습 중 기록은 줄마다 저장해서 잃지 않는다.

## 13. 홈 화면에 추가와 배포

- `manifest.webmanifest`(이름 "언어 1급", 아이콘, 흰 배경)를 넣어 휴대폰 홈 화면에 앱처럼 추가할 수 있게 한다.
- 서비스 워커 캐시는 단계 5에서 넣는다. 새 버전이 나오면 "새 버전이 있어요 · 새로고침"을 한 번 알린다.
- GitHub Actions: 테스트 → 빌드 → Pages 배포. 중계 함수는 `worker/`에서 따로 `wrangler deploy`. 키는 Workers 비밀값으로만 둔다.
